# nexora-core

Сетевое ядро Nexora без WireGuard. Два маленьких бинарника на Go:

| Бинарник | Где работает | Что делает |
|---|---|---|
| `nexora-engine.exe` | Windows-клиент (от администратора) | Перехватывает пакеты **только выбранных программ** и отправляет их на relay |
| `nexora-relay` | Linux-сервер (VPS) | Принимает пакеты, выпускает их в интернет со своего адреса, возвращает ответы |

Ничего не устанавливается в систему: нет виртуального адаптера, нет службы Windows,
нет изменений таблицы маршрутизации. Остановили процесс — всё вернулось как было.

## Как это работает

```
игра.exe ──пакет──▶ WinDivert (перехват) ──▶ nexora-engine
                                              │  чей это сокет? (таблица сокетов Windows)
                         не наша программа ◀──┤──▶ пакет возвращается в сеть как был
                                              │
                         выбранная программа ─┴──▶ шифрование ──UDP──▶ nexora-relay ──NAT──▶ игровой сервер
                                                                              │
игра.exe ◀──WinDivert (вброс ответа)◀── nexora-engine ◀──UDP── ответ ◀────────┘
```

1. Движок перехватывает каждый исходящий IPv4 TCP/UDP пакет и, **пока держит пакет**,
   спрашивает у Windows, какому процессу принадлежит локальный порт. Поэтому первый
   пакет соединения никогда не «проскакивает мимо».
2. Пакеты остальных программ возвращаются в сеть без изменений.
3. Пакет выбранной программы: адрес отправителя меняется на виртуальный адрес клиента,
   пакет шифруется (ChaCha20-Poly1305) и уходит на relay одним UDP-датаграммой.
4. Relay пишет пакет в TUN-интерфейс, ядро Linux делает NAT (MASQUERADE) и отправляет
   его игровому серверу. Ответ идёт обратно тем же путём.
5. Движок возвращает ответу настоящий локальный адрес и вбрасывает его как входящий.

Работают и TCP, и UDP. Соединение никогда не меняет путь посередине: что началось
напрямую — напрямую и закончится; если relay умер, уже идущие через него соединения
обрываются (а не «утекают» с другим адресом), новые идут напрямую.

## Сборка (с Mac, Linux или Windows — нужен только Go 1.26+)

```sh
GOOS=windows GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o dist/windows/nexora-engine.exe ./cmd/nexora-engine
GOOS=linux   GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o dist/linux/nexora-relay ./cmd/nexora-relay
```

Рядом с `nexora-engine.exe` должны лежать `WinDivert64.dll` и `WinDivert64.sys`
(есть в `third_party/windivert/`, версия 2.2.2).

Тесты: `go test ./...` (пакет `e2e` поднимает настоящий TUN и NAT — ему нужен Linux и root,
иначе он пропускается).

## Сервер (relay)

Любой Linux VPS с публичным IPv4. Нужен `iptables` (`apt install iptables`).

```sh
sudo install -m 755 nexora-relay /usr/local/bin/
sudo mkdir -p /etc/nexora
sudo nexora-relay init -out /etc/nexora/relay.json     # создаёт ключи, печатает публичный ключ
sudo cp deploy/nexora-relay.service /etc/systemd/system/
sudo systemctl enable --now nexora-relay
sudo ufw allow 4700/udp                                 # или правило в панели хостера
```

`relay.json` содержит приватный ключ и секрет токенов — права 600, никуда не копировать.

Полезные команды:

```sh
nexora-relay pubkey -config /etc/nexora/relay.json                         # публичный ключ для клиентов
nexora-relay token  -config /etc/nexora/relay.json -uid test -dev pc -ttl 24h   # тестовый токен
journalctl -u nexora-relay -f                                               # кто подключился / отключился
```

Несколько серверов: на каждом свой `init` (свой ключ), **`token_secret` на всех один и тот же** —
его же получит бэкенд, чтобы выдавать токены.

## Проверка на Windows

PowerShell **от имени администратора**, в папке с `nexora-engine.exe`:

```powershell
.\nexora-engine.exe probe 203.0.113.10:4700          # сервер отвечает? какой пинг?

.\nexora-engine.exe connect -relay 203.0.113.10:4700 -pubkey "<ключ>" -token "<токен>" -exe curl.exe
```

Во втором окне (обычном):

```powershell
curl.exe https://api.ipify.org     # должен показать IP СЕРВЕРА
```

а браузер на https://api.ipify.org должен показывать ваш **домашний** IP — значит,
через сервер идёт только выбранная программа. Для игры: `-exe game.exe` или
`-dir "C:\Games\Game"` (все программы из папки, включая античит и лаунчер).
Каждые 2 секунды движок печатает пинг до relay, потери и список соединений.

## Управление из приложения

`nexora-engine.exe serve -key-file <путь>` поднимает локальный API на `127.0.0.1:47600`.
Каждый запрос — с заголовком `X-Nexora-Key: <содержимое key-file>`.

| Запрос | Тело | Ответ |
|---|---|---|
| `GET /v1/status` | — | `running`, `tunnel` (пинг, потери, байты), `flows` (соединения по программам) |
| `POST /v1/start` | `{"relay","relay_public_key","token","rules":[{"name","exes":[],"dirs":[]}]}` | статус |
| `POST /v1/stop` | — | статус |
| `POST /v1/probe` | `{"relays":["host:port",…]}` | пинг до каждого сервера, лучший первым |

Интерфейс может быть написан на чём угодно и работать без прав администратора:
права нужны только движку (один запрос UAC при запуске).

## Токены

`base64url(JSON{"uid","dev","exp"})` + `.` + `base64url(HMAC-SHA256(token_secret, первая часть))`.
Бэкенд выдаёт такой токен вошедшему пользователю вместе со списком серверов
(адрес + публичный ключ). Relay проверяет подпись и срок сам, в базу не ходит.

## Ограничения этой версии

- Только IPv4 (IPv6-трафик игр идёт напрямую).
- Один relay на соединение; мультипуть (дублирование по нескольким маршрутам) не сделан.
- ICMP-ошибки от сети не доставляются программе.
- UDP-соединения, открытые до запуска движка, переключаются на relay; TCP — нет.
- Захват через WinDivert и поиск владельца сокета проверены только компиляцией —
  их нужно проверить на настоящей Windows (см. «Проверка на Windows»).
